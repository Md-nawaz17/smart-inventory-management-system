1. PROJECT SUMMARY
------------------
Smart Inventory Management System is a full-stack MERN inventory dashboard.
It allows authenticated users to manage their own product inventory, record
stock movement, view analytics, and export inventory data.

The application is built as two separate services:
- Backend API: Node.js, Express, MongoDB, Mongoose.
- Frontend app: React, Vite, Tailwind CSS.

Core user-facing features:
- Register and sign in with JWT authentication.
- Keep login state in localStorage or sessionStorage.
- View protected dashboard routes after authentication.
- Add, edit, delete, search, filter, and paginate products.
- Record stock-in and stock-out transactions.
- Prevent stock-out quantities from exceeding current stock.
- See total products, inventory value, category count, and low-stock count.
- See low-stock alerts using a shared 10-unit threshold.
- View stock by category and 30-day stock movement charts.
- Export products to an Excel .xlsx file.
- Toggle between light and dark mode.
- Use a responsive desktop/mobile dashboard shell.

The project is suitable for an educational or portfolio application. The main
flows use a real Express API and MongoDB database, not mocked data.

7. FRONTEND APPLICATION FLOW
----------------------------
Entry point:
- frontend/src/main.jsx renders the React app.
- frontend/src/App.jsx wires ThemeProvider, AuthProvider, BrowserRouter, lazy
  routes, and route guards.

Public routes:
- /login
- /register

Protected routes:
- /dashboard
- /dashboard/products
- /dashboard/analytics
- /dashboard/transactions

Redirect behavior:
- / redirects to /dashboard.
- Unknown routes redirect to /dashboard.
- Unauthenticated users trying to reach protected routes go to /login.
- Authenticated users trying to visit /login or /register go to /dashboard.

Lazy loading:
- Login, register, dashboard layout, dashboard, products, analytics, and
  transactions pages are lazy-loaded with React Suspense.
- xlsx is dynamically imported only when the user exports products.


8. FRONTEND ARCHITECTURE DETAILS
--------------------------------
Authentication:
- File: frontend/src/context/AuthContext.jsx
- login() calls POST /auth/login.
- register() calls POST /auth/register.
- logout() clears stored auth and resets the user state.
- Errors from auth routes are shown on login/register pages.

Auth storage:
- File: frontend/src/api/axios.js
- Token keys supported: token and inventoryToken.
- User keys supported: user and inventoryUser.
- "Keep me signed in" stores data in localStorage.
- Without "Keep me signed in", data is stored in sessionStorage.
- A 401 API response clears auth and redirects to /login.

API client:
- File: frontend/src/api/axios.js
- Base URL is VITE_API_URL or http://localhost:5000/api.
- Request interceptor attaches Authorization: Bearer <token>.
- Response interceptor handles unauthorized responses globally.

Theme:
- Files: frontend/src/context/ThemeContext.jsx and useTheme.js
- Theme is light/dark.
- Preference is saved and applied through the document root "dark" class.

Inventory refresh event:
- File: frontend/src/utils/inventoryEvents.js
- Event name: inventory:updated.
- Product add/edit/delete and transaction creation publish this event.
- DashboardLayout listens for it and refreshes the low-stock badge.

Layout:
- DashboardLayout.jsx creates the authenticated dashboard shell.
- Sidebar.jsx provides navigation.
- Topbar.jsx provides page title, theme toggle, notification indicator, user
  avatar/menu, and sign out.
- Mobile sidebar is a slide-in drawer with backdrop.

Dashboard page:
- File: frontend/src/pages/Dashboard.jsx
- Fetches low-stock products and analytics in parallel.
- Shows summary cards, analytics charts, low-stock alerts, and recent
  transactions.

Products page:
- File: frontend/src/components/dashboard/ProductTable.jsx
- Fetches up to 500 products from the backend.
- Performs search, category filtering, stock-status filtering, and 10-row
  pagination in the browser.
- Add product uses POST /products/add.
- Edit product uses PUT /products/:id.
- Delete product uses DELETE /products/:id after window.confirm().
- Export fetches GET /products/export and creates an Excel workbook.

Analytics page:
- File: frontend/src/pages/Analytics.jsx
- Fetches GET /products/analytics.
- Shows stock by category, stock movement, and category distribution.

Transactions page:
- File: frontend/src/components/dashboard/TransactionLog.jsx
- Fetches products for the selector.
- Fetches latest transactions.
- Records stock-in or stock-out through POST /transactions.
- Refreshes products and transaction history after successful submit.


9. BACKEND APPLICATION FLOW
---------------------------
Main server:
- File: backend/server.js
- Loads environment variables with dotenv.
- Requires MONGO_URI and JWT_SECRET.
- Exits early if required env vars are missing.
- Optionally configures DNS servers through DNS_SERVERS.
- Configures CORS for localhost/127.0.0.1 plus CLIENT_URL origins.
- Parses JSON request bodies.
- Connects to MongoDB before starting the HTTP listener.
- Root route returns: Inventory Management System API Running

Mounted routes:
- /api/auth -> backend/routes/authRoutes.js
- /api/products -> backend/routes/productRoutes.js
- /api/transactions -> backend/routes/transactionRoutes.js

Auth middleware:
- File: backend/middleware/authMiddleware.js
- Reads Authorization: Bearer <token>.
- Verifies JWT with JWT_SECRET.
- Loads user by decoded ID and excludes password.
- Returns 401 for missing, invalid, expired, or orphaned tokens.


10. DATABASE MODELS
-------------------
User model:
- File: backend/models/User.js
- Fields: name, email, password.
- Email is unique, lowercase, and trimmed.
- Password minimum length is 6.
- Password is hashed with bcrypt before save.
- matchPassword() compares a plain candidate password to the hash.
- Uses timestamps.

Product model:
- File: backend/models/Product.js
- Fields: user, productName, category, quantity, price, supplier.
- user is an indexed reference to User.
- quantity and price must be non-negative numbers.
- productName, category, and supplier are required trimmed strings.
- Uses timestamps.

Transaction model:
- File: backend/models/Transaction.js
- Fields: user, product, productName, type, quantity, date, note.
- user is an indexed reference to User.
- product is an indexed reference to Product.
- productName is a snapshot for history display.
- type must be stock-in or stock-out.
- quantity must be at least 1.
- note is optional.
- Uses timestamps.

Data isolation:
- Product and transaction queries always include the authenticated user ID.
- Users should not be able to access another user's inventory through normal API
  routes.


11. API ENDPOINTS
-----------------
Base URL:
- Local: http://localhost:5000/api

Auth endpoints:
POST /api/auth/register
- Body: name, email, password.
- Validates required fields.
- Requires password length of at least 6.
- Normalizes email.
- Rejects duplicate email with 409.
- Returns success, token, and safe user fields.

POST /api/auth/login
- Body: email, password.
- Normalizes email.
- Verifies bcrypt password.
- Returns 401 for invalid credentials.
- Returns success, token, and safe user fields.

GET /api/auth/me
- Requires Bearer token.
- Returns current user's id, name, and email.

Product endpoints:
All product endpoints require Bearer token auth.

POST /api/products/add
- Creates a product.
- Requires productName, category, quantity, price, supplier.
- Rejects negative quantity or price.

GET /api/products
- Query params: page, limit, search, category, status.
- status supports All, in-stock, low-stock, out-of-stock.
- Returns products, pagination, summary, and categories.

GET /api/products/export
- Returns all products owned by the current user, newest first.

GET /api/products/analytics
- Returns categoryData and movementData.
- movementData includes the last 30 days with zero-filled empty days.

GET /api/products/:id
- Returns one user-owned product.

PUT /api/products/:id
- Updates productName, category, quantity, price, supplier.
- Runs validators.

DELETE /api/products/:id
- Deletes one user-owned product.
- Deletes transactions associated with that product and user.

Transaction endpoints:
All transaction endpoints require Bearer token auth.

POST /api/transactions
- Body: productId, type, quantity, date, note.
- type must be stock-in or stock-out.
- quantity must be at least 1.
- Product must belong to the current user.
- Stock-out cannot exceed current quantity.
- Updates product quantity and creates transaction.

GET /api/transactions
- Returns latest 50 transactions for the current user.
- Populates product name/category if the product still exists.
- Sorts by transaction date and created time, newest first.


12. INVENTORY RULES
-------------------
Low-stock threshold:
- Shared threshold is 10 units.

Stock status:
- Out of stock: quantity equals 0.
- Low stock: quantity is greater than 0 and less than 10.
- In stock: quantity is 10 or greater.

Inventory value:
- Sum of product quantity * price.

Transaction behavior:
- stock-in increases product quantity.
- stock-out decreases product quantity.
- stock-out cannot exceed current quantity.

Audit/history behavior:
- Deleting a product also deletes its related transactions.
- This may be acceptable for a portfolio app, but it is a weakness for real
  accounting/audit usage.

16. KNOWN LIMITATIONS
---------------------
Testing:
- No automated backend test suite.
- No automated frontend test suite.
- No end-to-end test suite.

Backend correctness:
- Manual request validation is repeated in routes.
- No centralized Express error-handling middleware.
- No structured logger.
- No API rate limiting.
- No Helmet/security headers configuration.
- No request size limit beyond Express defaults.
- No MongoDB transaction for product quantity update plus transaction creation.
- Product deletion removes transaction history.

Authentication/security:
- JWTs are stored in Web Storage, so XSS prevention is important.
- No refresh-token flow.
- No password reset.
- No email verification.
- No MFA.
- No role-based access control.
- No account/profile management page.

Frontend UX:
- Product page downloads up to 500 records and then filters/paginates in the
  browser, even though the backend supports server-side pagination.
- Notification bell only indicates low stock; it does not open a panel.
- Error/success feedback is inconsistent and could use a toast system.
- Some flows log errors to console without user-facing feedback.
- Delete confirmation uses window.confirm instead of a custom dialog.
- Product modal should be reviewed for focus management.

Data model:
- No SKU field.
- No barcode field.
- No warehouse/location field.
- No reorder point per product.
- No unit of measure.
- No tax/discount/cost fields.
- No supplier entity/table.
- Category and supplier are free text and can drift by spelling/casing.
- Currency is displayed as Rs. and is not configurable.
- Historical inventory valuation is not stored.

Operations/deployment:
- No health endpoint beyond root text response.
- No monitoring/observability.
- No backup/restore guidance.
- No seed/demo data script.
- No CI workflow.

Codebase cleanup:
- Some legacy frontend files appear to remain from an earlier implementation.
- Confirm unused imports/files before deleting.
